# Production Foundation F0 Technical Plan

- Version: 1.0
- Status: Confirmed
- Date: 2026-08-04
- Target: v0.3.0-alpha.1

## Decision Summary

### D-001 Principal And Scope Separation

`identity.Actor` owns only stable principal fields. `authz.Request.Scope` is
derived by consumer code and evaluated against durable RBAC bindings. This
supports one actor across many scopes while preserving exact default-deny policy.

### D-002 Authentication Contract Split

Define narrow resolver, password verifier, session store/manager, and bearer
authenticator contracts. Browser transports own login ceremony. Local password
HTTP and OIDC HTTP contribute distinct routes while protected handlers depend
only on session authentication.

### D-003 PostgreSQL Session Component

Move reusable session persistence and issuance into the PostgreSQL component.
Local Identity owns development principals/passwords/tokens. OIDC uses the same
server-side session contract and durable actor registry without receiving raw
database or transaction authority.

### D-004 OIDC Separate Module

Create `github.com/iiwish/modary/components/oidc`. Use `coreos/go-oidc/v3` and
`golang.org/x/oauth2` for discovery, verification, exchange, and PKCE. The module
owns no MFA, password, or recovery logic. A disposable standards-compatible IdP
and hostile fixtures verify the flow.

### D-005 Process Runtime Boundary

Add a standard-library process package for build metadata, readiness gates,
bounded health checks, structured logs, server drain, and shutdown ordering.
Application lifecycle remains in `appkit`; process runtime wraps it explicitly.

### D-006 Explicit Migration Operation

Database components expose a bounded migration runner through a new command
path that validates the same Module graph and migration sources. Generated
servers choose migrate-on-start or require a completed migration-only step. No
reverse migration is introduced.

### D-007 Consumer-Owned Deployment Source

Starter emits Dockerfile, `.dockerignore`, and database-backed local Compose.
The final image is non-root and contains only the application binary and required
CA/timezone material. Kubernetes examples consume the same probe and signal
contract but are not generated by default.

### D-008 Structured Logging And Optional OTel

Root process and HTTP packages use `log/slog` only. Create
`github.com/iiwish/modary/components/otel` for OTel SDK, OTLP exporters, HTTP
instrumentation, and explicit shutdown. OTel logs remain out of F0; JSON slog to
stdout is the stable log transport.

### D-009 Release Train

Publish one immutable commit with root, PostgreSQL, governed PostgreSQL, OIDC,
and OTel annotated tags at `v0.3.0-alpha.1`. Hosted tag CI and remote consumers
must resolve all five modules without local replacements.

## Alternatives Considered

- Keeping Scope in Actor was rejected because it conflates authentication with
  product tenancy and prevents one identity from holding multiple bindings.
- Adding OIDC methods to the password Authenticator was rejected because it
  hides provider-specific redirects and callback state in a universal contract.
- Implementing OAuth/OIDC primitives directly was rejected as unnecessary and
  security-sensitive reinvention.
- Putting OTel APIs in the root module was rejected because unselected
  applications would inherit heavy dependencies and global provider semantics.
- Shipping Helm as the primary deployment surface was rejected because it binds
  framework adoption to Kubernetes and obscures the ordinary process contract.
- Relying only on startup migrations was rejected because rolling deployment
  needs an explicit, auditable schema phase.

## Constitution Check

- Empty Core stays free of database, identity, OIDC, OTel, and container runtime
  dependencies: satisfied through separate modules and source selection.
- Components remain explicit and removable: validated by module graph, route,
  config, generated-file, and runtime absence tests.
- Business data and deployment remain consumer-owned: generated artifacts are
  reference source, and platform services remain out of scope.
- Security and diagnostics fail closed: adversarial identity tests, bounded
  probes/attributes, secret redaction, and default-private operator surfaces.
- Published tags/migrations remain immutable: v0.3 uses new tags and forward
  migrations only.

No constitution violation is accepted.

## Risks And Mitigations

- Identity refoundation has broad compile impact. Mitigation: contract-first RED
  tests, mechanical call-site migration, copied-out local/OIDC consumers, and
  no compatibility wrapper.
- OIDC callback mistakes can create account takeover. Mitigation: maintained
  libraries, state/nonce/PKCE, strict redirect and issuer policy, one-use flow
  state, bounded inputs, uniform errors, and real-provider tests.
- Dependency readiness can cause cascades. Mitigation: liveness is local only;
  readiness checks are bounded, concurrent-safe, cached only under explicit
  policy, and documented not to restart the process.
- Telemetry can leak secrets or explode cardinality. Mitigation: approved
  semantic fields, route templates only, no actor/scope/raw-path labels, tests
  for attribute rejection, and explicit exporters.
- Container tests can become slow or platform-specific. Mitigation: source tests
  plus one Linux container acceptance on hosted CI; ordinary cross-build remains.

## Consequences For Tasks

T042 changes the public identity/scope contract before any adapter work. T043
builds OIDC only after those contracts are accepted. T044 establishes the
process runtime used by T045 deployment and T046 telemetry. T047 composes every
selected and unselected external consumer. T048 performs the immutable release.
